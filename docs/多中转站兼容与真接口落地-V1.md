## 1. 多中转站兼容架构

### 1.1 三层设计

```
┌─ 数据层（MySQL，可后台改）──────────────────────────────┐
│  model_channels    一家中转站：base_url / api_key / 协议模板 │
│  model_endpoints   一个模型的一个接入点：channel_id + 排序 │
│      · template_json  ← 协议差异全外置为 JSON 路径/模板串   │
└───────────────────────────────┬────────────────────────┘
                                ↓
┌─ 适配层 ────────────────────────────────────────────────┐
│  RelayAdapter：通用适配器，按 template_json 渲染请求/解析 │
│  JsonPath：零异常 JSON 路径解析（result.data[0].url）     │
└───────────────────────────────┬────────────────────────┘
                                ↓
┌─ 路由层 ────────────────────────────────────────────────┐
│  ChannelRouter：按 sort_order 排候选 → 逐站提交            │
│      失败（429/5xx/超时/网络）→ 立刻切下一站              │
│      熔断通道跳过；成功后粘住该站                          │
└─────────────────────────────────────────────────────────┘
```

### 1.2 「加一个新中转站」的操作步骤（无需写代码）

```sql
-- 1) 插一个通道
INSERT INTO model_channels
  (id, name, provider, base_url, api_key, protocol, template_json,
   capabilities, priority, rpm_limit, cost_ratio, status, remark, created_at, updated_at, updated_by)
VALUES
  ('ch_new', 'NewRelay', 'relay', 'https://new-relay.example.com',
   '<AES 密文>', 'openai-image',
   '{"submit_path":"/v1/images/generations",
     "poll_path":"/v1/images/generations/{task_id}",
     "request_template":{"model":"{upstream_model}","prompt":"{prompt}","size":"{size}","n":"{n}"},
     "task_id_path":"id","status_path":"status","result_urls_path":"data[0].url"}',
   'image', 30, 600, 1.0000, 'active', '第二备份站', NOW(), NOW(), 'admin');

-- 2) 插一个接入点（sort_order 决定回退顺序）
INSERT INTO model_endpoints
  (id, model_key, display_name, channel_id, base_url, upstream_model,
   timeout_ms, max_retries, sort_order, enabled, param_map_json, template_json,
   created_at, updated_at, updated_by)
VALUES
  ('ep_new_t2i', 'image.t2i.2k', '备用图片通道', 'ch_new',
   'https://new-relay.example.com', 'gpt-image-2',
   60000, 2, 20, 1, '{}', NULL, NOW(), NOW(), 'admin');
```

`api_key` 列存 AES 密文（`SecretBox`），**不要写明文**。密文可用后台接口
`POST /api/v1/admin/channels` 生成（该接口会加密后落库并只回掩码）。

### 1.3 协议差异如何配置（template_json 字段说明）

| 字段 | 含义 | 示例 |
|---|---|---|
| `submit_path` | 提交路径（相对 base_url） | `/v1/images/generations` |
| `poll_path` | 轮询路径，含 `{task_id}` | `/v1/images/generations/{task_id}` |
| `auth_header` / `auth_prefix` | 鉴权头与前缀 | `Authorization` / `Bearer ` |
| `request_template` | 请求体模板，值支持 `{prompt}` `{size}` `{n}` `{upstream_model}` 等占位符 | 见上 |
| `task_id_path` | 上游任务 ID 在响应里的路径 | `id` |
| `status_path` | 上游状态字段路径 | `status` |
| `result_urls_path` | 结果 URL 列表路径 | `result.data[0].url` 或 `data[*].url` |
| `status_map` | 上游状态 → 平台四态（pending/running/succeeded/failed） | `{"completed":"succeeded"}` |
| `extra_headers` | 额外请求头（如某站要 `X-API-Key`） | `{"X-API-Key":"..."}` |

**占位符类型保留**：模板值若是「单个占位符」（如 `"{n}"`），替换时保留参数原始类型 ——
`n=1` 是数字 `1` 而非字符串 `"1"`，否则严格上游会返回 400/403。

**内置协议模板**（`template_json` 为空时自动套用）：
`toapis` / `toapis-video` / `openai-image` / `openai-video`。

### 1.4 回退判定规则

| 上游情况 | 错误码 | 是否回退下一站 |
|---|---|---|
| HTTP 429 限流 | `channel.rate_limited` | ✅ 回退 |
| HTTP 5xx | `channel.upstream_error` | ✅ 回退 |
| 连接失败 / 超时 | `channel.request_failed` | ✅ 回退 |
| HTTP 4xx 参数错误 | `channel.bad_request` | ❌ 不回退（改参数也没用） |
| 上游明确生成失败 | `channel.failed` | ❌ 不回退（已提交，换站要重扣费） |

**扣费只在 submit 阶段冻结一次**，回退只换上游不动账 —— 全部失败才全额退回冻结积分。

### 1.5 熔断

`model_channels.circuit_state`（closed / open / half_open）+ `consecutive_failures`。
连续失败达到阈值后该通道进入冷却，冷却期内在 `ChannelRouter.plan()` 阶段直接跳过，
不再浪费一次请求超时。冷却结束后半开探测，成功则恢复。

## 2. MySQL 迁移

| 项 | 内容 |
|---|---|
| 连接 | `jdbc:mysql://127.0.0.1:3306/xin_ai`，`root/root`（可用环境变量覆盖） |
| 驱动 | `mysql-connector-j` |
| 迁移 | Flyway 10 + `flyway-mysql` |
| 脚本 | `V1__business_tables.sql`（47 张表）→ `V2__seed_data.sql`（种子数据） |

**MySQL 8 方言修正**（原 PostgreSQL 版踩过的坑）：
- `TEXT` / `LONGTEXT` 列**不能带 DEFAULT**（MySQL 8 报 `BLOB/TEXT column can't have default value`）→ 已全部去掉默认值
- 迁移版本顺序：先建表（V1）再插数据（V2），避免 `V1__init.sql` 插入尚不存在的表

**存储分层**：
- 通用领域实体（users / tasks / quotes / ledger / assets 等）→ `entity_rows(entity_type, row_id, user_id, data LONGTEXT, created_at, updated_at)`，`MySqlDataStore` 负责 JSON 序列化
- 中转站配置（`model_channels` / `model_endpoints`）→ **关系型专表**，`RelayConfigService` 用 `JdbcTemplate` 直管

**已知坑**：`MySqlDataStore` 早期版本只关 `PreparedStatement` 没关 `Connection`，
导致 HikariCP 连接池耗尽（`CannotGetJdbcConnectionException`）。现已全部改为 try-with-resources 三件套。

## 3. Redis 本地化

| 项 | 内容 |
|---|---|
| 地址 | `127.0.0.1:6379` |
| 用途 | 短信验证码（写+读）、发送冷却（`SET NX` + TTL）、会话、幂等键 |
| 降级 | Redis 不可达时自动切内存实现，**不阻塞应用启动与运行** |

验证：同一手机号第二次请求 `POST /auth/sms/send` 返回 **HTTP 429**（冷却生效）。

## 4. 积分有效期两年（按充值时间计）

- 每次充值生成一条 `billing_points_batches` 记录：
  `expire_at = 充值时间 + 2 年`（`BillingService.POINTS_VALID_YEARS = 2`）
- 本金与赠送分别建批次（`source_type` = `recharge` / `bonus` / `adjust`），到期时间相同便于对账
- `GET /api/v1/points/balance` 的 `expires_at` 取**最早到期的未过期批次**；无批次返回「永久有效」
- 初始赠送积分不建批次 → 新用户余额显示「永久有效」

## 5. 前端从 mock 切真接口

### 5.1 代理方案

`apps/web/next.config.ts` 加 rewrite：`/api/v1/:path*` → `http://127.0.0.1:3001/api/v1/:path*`。
浏览器侧同源，不需要后端开 CORS；换后端只改 `BACKEND_ORIGIN` 环境变量。

### 5.2 新增封装层 `apps/web/src/lib/backend/`

| 文件 | 覆盖接口 |
|---|---|
| `auth.ts` | `/auth/sms/send`、`/auth/sms/verify`、`/auth/password/login`、`/auth/logout` |
| `tasks.ts` | `/tasks/quote`、`/tasks/submit`、`/tasks/{id}`、`/tasks` |
| `points.ts` | `/points/balance`、`/points/ledger`、`/recharge/orders` |
| `assets.ts` | `/assets`、`/assets/upload-policy`、`/assets/complete`、`/assets/{id}`、`/assets/batch-delete`、`/asset-groups` |

### 5.3 已改造的页面

| 页面 | 改动 |
|---|---|
| `toolbox/image-generation` | 报价 → 提交 → 轮询终态 → 展示上游真实图片 URL；提交按钮显示实时进度百分比 |
| `toolbox/video-generation` | 同上；结果用 `<video>` 播放；宽高比/时长/分辨率传给上游 |
| `account`（我的积分） | 余额与明细走 `/points/balance` + `/points/ledger`；类型筛选映射到后端 ledger type |
| `assets`（资产库） | 列表走 `/assets`；上传走 upload-policy → 直传 → complete；删除/重命名走真实接口 |
| 登录弹窗 `LoginModal` | 真实调 `/auth/sms/send` + `/auth/sms/verify`；体验版后端回传 `dev_code` 自动填入 |

### 5.4 关键坑：Jackson 全局 snake_case

后端 `application.yml` 配了 `spring.jackson.property-naming-strategy: SNAKE_CASE`，
**请求体字段也必须用 snake_case**。写 `assetId` 后端拿到 `null` → `complete` 返回 404。
前端封装里请求体统一用 `asset_id` / `package_code` / `pay_method` / `model_key` / `quote_fingerprint`。

### 5.5 关键坑：任务不会自己跑

`POST /tasks/submit` 只建单 + 冻结积分，**不会**自动跑上游。
新增 `TaskWatchdog`（`@Scheduled` 每 2 秒扫描 `pending` 任务并投递到 IO 线程池）+
`ApiApplication` 上加 `@EnableScheduling`。没有它任务永远停在 pending，前端只看到「提交中」。

## 6. 端到端验证结果（2026-11-07 实测）

### 6.1 图片生成（真实 ToAPIs）

```
报价 points=4 fingerprint=gUCtSejAQ_Im3gSJ...
任务 tsk_d981a3f6f89e → status=succeeded channel_id=ch_toapis
result.result_urls = [https://files.toapis.cn/images/tsk_img_01M6S69HKPHGZ441X4WHR7H0G2/1793994358_e44cc9d5.png]
billing = {status: settled, credits: 4, cost_usd: 0.02}
```
浏览器端验证：提示词 → 点击生成 → 约 90s 后结果区出现上游真实 PNG。

### 6.2 多中转站回退

死站 `ch_dead`（`http://127.0.0.1:19999`，sort_order=5）先命中并连接失败，
路由立刻切到 `ch_toapis`（sort_order=10）成功出图。
后端日志可见连续两条「上游提交」：先是死站、后是 ToAPIs。

### 6.3 视频生成（真实 ToAPIs）

```

t+10s running 50 → t+80s running 99 → t+90s succeeded

### 6.4 积分与流水

```

### 6.5 资产库

POST /assets/complete       → 资产落库可见
DELETE /assets/{id}、POST /assets/batch-delete、PATCH /assets/{id} 均验证通过
